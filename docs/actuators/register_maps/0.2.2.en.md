# 0.2.2

Software version: `0.2.2`; configuration version: `0.2`. This table is based on the CAN configuration-register implementation in source commit `6f84334`.

See the [Motor Register Communication Protocol](../register_protocol.md) for CAN read/write commands, frame formats, status codes, and little-endian decoding.

## Usage Notes

- `type=0`: `int32_t`; `type=1`: `bool`; `type=2`: IEEE754 single-precision `float`; `type=4`: version number.
- Access level `0`: runtime read/write; `1`: writable only in menu or error state; `2`: system communication parameter, writable only in menu or error state; `3`: read-only.
- A write operation only changes RAM. Send `REG_SAVE` after a successful write to retain the value across power cycles.
- `current_test_enable` and `mit_aux_enable` are runtime switches and are not written to Flash. `REG_SAVE` stores them as `0` without changing their current RAM state; they return to `0` after power-up or configuration reload.
- A full ENCO build exposes 52 registers. Addresses `0x13`, `0x15`, `0x17`, and `0x18` exist only when `USE_ENC2=1`; a build without ENCO exposes 48 registers. Query `REG_INFO` for the actual count.
- The communication layer primarily validates the address, data type, and write state; it does not enforce a common business range for every numeric value. Confirm the target motor model and parameter requirements before changing protection thresholds, limits, or control gains.
