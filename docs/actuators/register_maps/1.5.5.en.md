# 1.5.5

Software version: `1.5.5`; configuration version: `1.5`.

See the [Motor Register Communication Protocol](../register_protocol.md) for CAN read/write commands, frame formats, status codes, and little-endian decoding. Reading `0x7C` returns `type=4` and `value_raw=0x00000105`, indicating configuration version `1.5`; confirm the full software version from the boot information.

## Usage Notes

- `type=0`: `int32_t`; `type=1`: `bool`; `type=2`: IEEE754 single-precision `float`; `type=3`: `uint32_t`; `type=4`: version number. A `bool` still occupies a 4-byte value, and a nonzero write is normalized to `1`.
- Access levels indicate permissions: `0` runtime read/write; `1` writable only in menu or error state; `2` system communication parameter, also writable only in menu or error state; `3` read-only. They do not specify numeric limits.
- The table below lists the **57** registers for a standard motor with an AC4754 output encoder. `REG_INFO` reports **50** non-read-only registers, with `value_raw=0x00320039`; this is not the number writable in the current state.
- Writes normally change RAM only; send `REG_SAVE` for persistence across power cycles. Address `0x24` schedules an automatic save, and runtime test switches have persistence exceptions, as described below.
- Numeric writes primarily validate the address, type, and state permissions, without applying a common set of application-specific limits. Configure current, torque, gains, and protection thresholds for the actual motor variant. Communication encoding ranges do not describe mechanical limits or capability under load.

!!! warning "Key Differences from Older Tables"

    Address `0x24` has changed from `aging_test_enable` (`type=1`, `bool`) in 1.4.1 to the `aging_test_status` (`type=3`, `uint32_t`) bitmap. Writing with the old type returns `status=5`. A successful write schedules a save of the entire current configuration, which can also write other unsaved RAM parameters to Flash.

    New registers are `enco_use` at `0x17`, `enco_boot_sync_use` at `0x18`, and `motor_thermal_observer_enable` at `0x56`. Do not apply older versions' definitions for the same addresses.

## Firmware Variants

| Firmware | Public Registers | Non-Read-Only Registers | `REG_INFO value_raw` |
| --- | ---: | ---: | --- |
| Standard motor with an AC4754 output encoder | 57 | 50 | `0x00320039` |
| Gripper firmware | 52 | 43 | `0x002B0034` |

Gripper firmware does not expose `0x13`, `0x15`, `0x16`, `0x17`, or `0x18`; addresses `0x35`, `0x36`, `0x6A`, and `0x6B` change to access level `3` (read-only). Gripper CAN motion fields use displacement in mm, velocity in mm/s, and force in N. Do not apply the units or encoding ranges of standard motor MIT motion fields directly.

Addresses `0x17` and `0x18` are exposed only for standard motors with an AC4754 output encoder. Use `enco_use` to configure ENCO use during normal operation.

## Persistence and Version Compatibility

- `enco_use`, `enco_boot_sync_use`, and `motor_thermal_observer_enable` can be saved with the configuration. For standard motors with an AC4754 output encoder, the factory defaults are `enco_use=1` and `enco_boot_sync_use=0`; the thermal observer default depends on the motor variant. The factory default for `enc2_closed_loop_enable` is `1`, subject to the ENCO validity requirements.
- `current_test_enable`, `backlash_test_enable`, `mit_aux_enable`, and `runtime_state` are written to Flash as `0` during a save, then restored to their runtime values in RAM after the save finishes; reloading the configuration resets them to zero.
- After loading the configuration, `reduction_ratio` is set to the value for the current motor variant. Default current, torque, and thermal model parameters also depend on the motor variant; there is no single default table applicable to every motor.
- In addition to the CRC and configuration version, the current firmware checks a configuration layout marker. If the CRC is valid but the version or marker does not match, startup reports an incompatible configuration and saving is blocked. An older configuration labeled `1.5` therefore cannot be assumed to be directly reusable.
